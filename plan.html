SLEEKTECH / PRODUCT STRATEGY / 01 NOVEMBER 2026

One business.
Two connected workspaces.

Build a CRM for revenue operations and project delivery, and a Talent platform for recruitment and candidate self-service. Both applications use Next.js and share a Node.js API and MongoDB document model. The existing SleekTech careers page reads published roles from the same API.

Business journeys

CRM: New lead → Qualification → Proposal → Negotiation → Won → Customer → Delivery project. Losing a deal preserves its history. Converting twice must return the same client.

Talent: Published role → Sign in → Upload and review résumé → Complete application → Screening → Interview → Offer → Hired. Candidates can withdraw. Recruiters make decisions; AI does not score, rank or automatically reject applicants.

Research and product decisions

  • HubSpot’s CRM scope supports centering the workspace on contacts, deals, tasks and connected communication. SleekTech additionally links won opportunities directly to delivery.
  • Greenhouse scorecards use predefined criteria and interviewer feedback. Talent will record rubric scores and evidence, rather than an opaque AI suitability score.
  • WhatsApp messaging rules distinguish a 24-hour customer-service window from approved templates outside it. Capture opt-in and enforce the window on the server.
  • Apple Mail Privacy Protection can load remote content without recipient engagement. Label opens as signals; delivery and replies are separate events.
  • Resend webhook verification requires signed raw payloads. Verify before storing events and deduplicate retries.
  • OWASP upload guidance informs authenticated uploads, file signatures, limits, generated file names, private storage and malware scanning.
  • OpenAI Structured Outputs supports typed extraction. Treat résumé content as untrusted data, validate output, and ask the candidate to confirm extracted fields.

Use a modular monolith so transactions and permissions stay straightforward. Local development uses MongoDB replica sets; deployed installations use a secured MongoDB replica set or Atlas cluster. The frontends have no provider secrets and never query the database directly. Candidate registration cannot grant staff privileges. This release serves one SleekTech organization; multi-tenant SaaS is a separate architecture milestone.

Data relationships

Users → sessions and candidate profiles. Leads → clients → projects. Leads → messages → delivery events. Jobs → applications ← candidates. Applications → stage history, interviews and scorecards. Résumés are owned by candidates and available only to authorized recruitment staff. The existing website receives only published job fields.

3. Design specification

Use the existing SleekTech symbol and Inter font. Cobalt #185bf1 is reserved for primary actions, active navigation and focus. Charcoal #15181d, muted gray #616773 and thin #dedfe3 borders carry information. White surfaces, restrained 6–10px radii and spacious layouts keep the applications related to the editorial marketing site.

Surface Layout and behavior
CRM workspace Compact left navigation, contextual page header, four useful metrics, revenue pipeline, next actions, recent activity. Tables have search and meaningful empty states. Lead detail opens in a focused dialog; conversion creates a customer without losing history.
Talent workspace Same shell with recruitment navigation. Requisitions, candidate stages, interview details and scorecards share clear status language. Published and draft jobs remain visibly distinct.

4. Delivery and acceptance

  1. Complete research and this plan, then establish the shared design system.
  2. Implement the shared API and persistent core data, followed by both Next.js workspaces.
  3. Connect the marketing careers page to published jobs and candidate applications.
  4. Test role isolation, lead conversion idempotency, job visibility, candidate ownership, file validation, stage history, webhook security and the complete application journey.
  5. Activate provider accounts and validate real delivery on a staging domain before public launch.

Provider credentials, a verified sender domain, a WhatsApp Business phone number and approved templates are operational prerequisites for live integrations. The secure OpenAI project selection is pending. Local demonstration records must remain explicitly labeled and must never send messages.

Production launch also requires organization-specific privacy and retention settings, verified email/recovery, backups, infrastructure monitoring and security review. These are tracked release gates, not claims that this first implementation is ready for unrestricted public deployment.

Scope assumption: SleekTech’s internal sales and hiring operations. Currency defaults to INR and can be changed in the formatter. No real customers, applicants or job vacancies are invented; example records appear only in explicitly enabled local demo mode.
